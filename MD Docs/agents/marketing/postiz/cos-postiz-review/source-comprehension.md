# Source Comprehension: Agents Info & Recommended Architecture (Postiz Review)

This document establishes the normative baseline for the Marketing Agent and its integration with the Chief of Staff (CoS) agent within the **Local-First Federated Multi-Agent Business OS**, based on `MD Docs/Agents info.md` and `MD Docs/Recommended architecture.md`.

## 2. Marketing Agent Capability Decomposition & Scope Ownership

`Agents info.md` (lines 16–28) defines the Marketing Agent as an entity that:
> *"Creates posts, edits videos, tracks metrics"*

Below is the decomposition into its four normative capabilities and their exact mapping between **Postiz** and **Chopify**:

| # | Normative Capability | Specification Definition (`Agents info.md`) | Implementing Component in Repo | Verification Status & Code Evidence | Scope Ownership Verdict |
|---|---|---|---|---|---|
| **C1** | **Create social posts** | *"Captions and carousels in your brand voice."* | `business-os/agents/marketing/postiz-app` | **IMPLEMENTED** (`FACT`). Postiz implements post creation, captioning, carousels/attachments, and thread drafting via REST (`POST /public/v1/posts`, `public.integrations.controller.ts:147`), MCP tool (`integrationSchedulePostTool`, `integration.schedule.post.ts:62`), LangGraph post generator (`AgentGraphService.createGraph`, `agent.graph.service.ts:112`), and Mastra Copilot (`copilot.controller.ts:48`). | **Primary: Postiz** |
| **C2** | **Edit short form videos** | *"Cut long videos into captioned reels."* | `business-os/agents/marketing/chopify` & `postiz-app` | **OVERLAPPING / DIVERGENT** (`FACT`).<br>• *Chopify:* Implements local-first cutting, transcription, and caption rendering (`chopify.py`, `render_clips.py`, `score_clips.py`, `captions.py`) without external cloud GPU billing.<br>• *Postiz:* Contains an alternative cloud-dependent clipping pipeline (`apps/orchestrator/src/workflows/clipping.workflow.ts`, `clipping.tool.ts:11`) requiring RunPod Serverless GPU/CPU, Cloudflare R2, Deepgram, and OpenAI (`UploadFactory.clippingEnabled()`). | **Primary Local: Chopify**<br>*(Postiz cloud clipping is secondary/redundant)* |
| **C3** | **Schedules and publishes** | *"Posts at your best time on every platform."* | `business-os/agents/marketing/postiz-app` | **IMPLEMENTED** (`FACT`). Postiz provides automated scheduling and multi-platform publishing to 28+ channels via Temporal workflows (`post.workflow.v1.1.2.ts`, `apps/orchestrator/src/activities/post.activity.ts:515`), slot finder (`GET /public/v1/find-slot/:id`), social platform adapters (`libraries/nestjs-libraries/src/integrations/social/`), and calendar UI. Chopify explicitly excludes publishing (`docs/product.json:30`). | **Exclusive: Postiz** |
| **C4** | **Analyzes metrics** | *"Weekly report on what worked and what's next."* | `business-os/agents/marketing/postiz-app` | **PARTIAL** (`FACT`). Postiz implements channel-level and post-level analytics querying via REST (`GET /public/v1/analytics/:integration` and `GET /public/v1/analytics/post/:postId`, `public.integrations.controller.ts:700, 710`), `AnalyticsController` (`apps/backend/src/api/routes/analytics.controller.ts`), and `digest.email.workflow.ts`. However, automated weekly report generation and synthesis into executive scorecards is unbuilt. | **Primary Data: Postiz**<br>*(Synthesis belongs to CoS)* |

### Postiz vs Chopify Capability Reconciliation Summary
1. **Postiz owns C1 (Social Posts), C3 (Scheduling & Publishing), and C4 (Raw Metrics Collection).** It holds social media platform credentials, OAuth tokens, rate limiters, and Temporal scheduling queues.
2. **Chopify owns C2 (Short-Form Video Editing) under the Local-First Federated architecture.** Postiz's internal clipping module requires third-party cloud infrastructure (RunPod, Deepgram, Cloudflare R2).
3. **Missing Bridge:** There is currently no file, webhook, or API bridge between Chopify's rendered output and Postiz's upload pipeline. Chopify renders clips to local disk (`.mp4`), but no automated adapter calls `POST /public/v1/upload` or `integrationSchedulePostTool` to schedule them in Postiz.

## 4. Source Discrepancies and Open Ambiguities (`OPEN`)

1. **Absence of Shared Event Bus in Postiz Repo (`OPEN`):**
   - `Recommended architecture.md` (lines 23, 62) mandates Redis as the cross-agent event bus ("Redis: Events and asynchronous communication... Redis events").
   - Postiz utilizes Redis (`REDIS_URL`, `postiz-redis:6379`, `ioRedis` in `libraries/nestjs-libraries/src/redis/redis.service.ts`) strictly for internal caching, rate limiting (`Throttler`), and OAuth temporary state keys (`login:${state}`, `organization:${state}`, `refresh:${state}`).
   - *Resolution:* Postiz does not publish domain lifecycle events (e.g. `post.created`, `post.published`, `post.failed`) to Redis pub/sub or Redis streams. The CoS cannot monitor Postiz via Redis events without an explicit adapter or codebase addition.

2. **Absence of Qdrant Vector Store in Postiz Repo (`OPEN`):**
   - `Recommended architecture.md` (lines 22, 61) mandates PostgreSQL + Qdrant for shared business intelligence and RAG.
   - Postiz stores its application data in PostgreSQL (`Organization`, `Post`, `Integration`), uses `@mastra/pg` for agent chat memory (`mastra.store.ts:3`), and uses LangGraph in memory with Tavily search (`agent.graph.service.ts:7`). Qdrant is completely absent.
   - *Resolution:* Brand guidelines, tone of voice embeddings, and business catalog context must be supplied by the external CoS in command payloads, or a shared Qdrant adapter must be introduced.

3. **Duplication of Video Clipping Capability (`OPEN` - Scope Arbitration):**
   - Postiz ships a complete video clipping subsystem (`clipping.workflow.ts`, `clipping.tool.ts`, `clipping.controller.ts`) that mirrors Chopify's purpose.
   - However, Postiz's implementation is tightly coupled to cloud SaaS providers (RunPod Serverless, Deepgram, Cloudflare R2, OpenAI) requiring dedicated billing and accounts (`UploadFactory.clippingEnabled()`).
   - *Resolution:* In line with the "Local-First Federated Multi-Agent Business OS" philosophy, Chopify is the primary video editor. Postiz's clipping features should be treated as redundant cloud-only fallbacks, and integration efforts must prioritize connecting Chopify's local rendering directly into Postiz's upload API.
