Below is a **nine-task implementation plan for the Product / Evidence Engine (`W_PROD`)**, based on the attached research. Tasks are sequential; numbered items within each description are subtasks. Owners are suggested roles.

| Task ID   | Phase                            | Task Name                                        | Description                                                                                                                                                                                                                                                                                                                                                                                                                                            | Predecessor | Milestone                                                                               | Resource / Owner                                                          |
| --------- | -------------------------------- | ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------- | --------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| **PE-01** | Assessment                       | Inspect Existing Implementation and Confirm Gaps | **1.1** Inspect the existing `product_evidence_engine`, S_VAL skill, shared contracts, clients and tests. **1.2** Confirm Model-A boundaries and record baseline test results. **1.3** Produce the smallest justified ADD/MODIFY list before coding; reuse existing functionality wherever sufficient.                                                                                                                                                 | None        | **M1:** Implementation baseline and necessary changes documented                        | Backend Architect; Backend Engineer                                       |
| **PE-02** | Contract Design                  | Define Product, Evidence and Task Schemas        | **2.1** Define bounded worker/specialist task and result contracts. **2.2** Specify records for formulations, laboratory results, sources, evidence assessments, claims, regulatory rules, conflicts and gaps. **2.3** Define versioning, validation rules and provenance links using existing artifact and PROV contracts.                                                                                                                            | PE-01       | **M2:** Machine-validatable contracts and synthetic fixtures established                | Backend Architect; Backend Engineer; QA Engineer                          |
| **PE-03** | Execution Infrastructure         | Configure S_VAL and Independent Model Profiles   | **3.1** Configure all six specialists through the existing sandbox and provider-neutral LLM clients. **3.2** Give each specialist an independently configurable model profile, budget and permitted tools. **3.3** Verify isolation, governed network access, bounded results and denial of direct IE, RAG, database, CMS and parent-runtime access.                                                                                                   | PE-02       | **M3:** Sandbox execution and independent model routing verified                        | AI Engineer; Backend Engineer; Security Engineer                          |
| **PE-04** | Research Capability              | Implement Discovery and Source Capture           | **4.1** Implement the **Discovery & Source Capture** specialist with explicit questions, search criteria and stopping rules. **4.2** Retrieve permitted sources through AIO sandbox web capabilities. **4.3** Capture source identifiers, locations, retrieval dates, jurisdiction, evidence type, freshness and provenance; record duplicates, exclusions and inaccessible evidence.                                                                  | PE-03       | **M4:** Reproducible research output with traceable sources produced                    | AI Engineer; Research Methodologist                                       |
| **PE-05** | Product and Laboratory Evidence  | Implement Formulation and Lab Validation         | **5.1** Implement the **Product/Formulation & Lab Evidence** specialist. **5.2** Normalize ingredient identity, concentrations, units, product versions and batch/sample references. **5.3** Check report authenticity, methods, laboratory scope, uncertainty and supplied limits; assess whether ingredient or test evidence applies to the finished product.                                                                                        | PE-04       | **M5:** Traceable product specification and lab/relevance assessments produced          | Backend Engineer; Formulation Specialist; Laboratory QA Reviewer          |
| **PE-06** | Scientific Assessment            | Implement Evidence Appraisal and Safety Review   | **6.1** Implement the **Evidence Appraisal & Conflict/Gap Analysis** and **Safety Evidence** specialists. **6.2** Assess methodological quality, relevance, precision, consistency, exposure and safety coverage. **6.3** Cross-check critical findings, preserve contradictory results and identify evidence gaps; escalate serious safety concerns and unsupported conclusions.                                                                      | PE-05       | **M6:** Evidence-quality and safety assessments produced with explicit limitations      | AI Engineer; Research Methodologist; Qualified Safety Assessor            |
| **PE-07** | Claims and Regulatory Assessment | Implement Claim Mapping and Jurisdiction Checks  | **7.1** Implement the **Claim Mapping & Interpretation** and **Regulatory Applicability & Compliance Research** specialists. **7.2** Identify explicit and implied claims from wording, imagery, testimonials and qualifications; map each interpretation to relevant evidence. **7.3** Evaluate product classification, jurisdiction, rule authority and effective dates; flag unsupported claims and unresolved legal requirements for human review. | PE-06       | **M7:** Claim–evidence–source–rule mappings completed or explicit gaps recorded         | AI Engineer; Claims Reviewer; Regulatory Specialist                       |
| **PE-08** | Workflow Integration             | Assemble the Evidence Dossier and IE Handoff     | **8.1** Connect intake, decomposition, research, extraction, appraisal, cross-checking, claim mapping and compliance assessment within W_PROD. **8.2** Rerun conflict/gap analysis across the complete findings and assemble the dossier using deterministic S_VAL functions. **8.3** Validate references and provenance; implement bounded retries, partial results and review-needed evidence envelopes through existing IE contracts.               | PE-07       | **M8:** Complete draft dossier returned to IE with traceability and review requirements | Backend Engineer; AI Engineer; QA Engineer                                |
| **PE-09** | Verification and Human Review    | Validate Boundaries, HITL and Release Readiness  | **9.1** Execute the specified contract, evidence-mapping, laboratory, regulatory, provenance and LLM-routing tests, including actual sandbox isolation tests. **9.2** Demonstrate approve, reject, revise and hold flows through existing IE/HITL services; verify that changed dossier versions invalidate prior approval scope. **9.3** Resolve blocking defects and document configuration, limitations, recovery and handover.                     | PE-08       | **M9:** Required tests pass and the reviewed staging workflow is ready for handover     | QA Engineer; Security Engineer; Qualified Domain Reviewers; Product Owner |

**Boundary throughout:** W_PROD produces specifications, assessments and evidence dossiers. IE retains data mediation, persistence, canonical state and approval routing. Material claims, compliance conclusions and externally published dossiers require human review; structural validation alone does not establish safety or legal approval.
